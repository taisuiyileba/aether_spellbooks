# Aether Spellbooks 1.2.0 — NeoForge 1.21.1

Forge 1.20.1 版本位于同仓库的 [`1.20.1` 分支](https://github.com/taisuiyileba/aether_spellbooks/tree/1.20.1)。本目录是独立的 Minecraft 1.21.1 移植工程，保留 16 个法术、两种施法生物、两座神殿、法术书、饰品、两套盔甲和法杖／法剑，并包含地牢宝库与守卫召回。

原创代码及素材采用 [MIT License](LICENSE)。第三方模组、运行时引用的模型与纹理仍遵循各自许可证；本工程不将这些依赖打包进发布 JAR。

## 环境与依赖

使用 Java 21。开发依赖固定如下，Gradle 会自动下载：

| 依赖 | 验证版本 |
|---|---|
| Minecraft | 1.21.1 |
| NeoForge | 21.1.248 |
| Iron's Spells 'n Spellbooks | 1.21.1-3.16.3 |
| The Aether | 1.21.1-1.5.10-neoforge |
| Iron's Lib | 1.21.1-2.1.0 |
| GeckoLib | 4.7.5.1 |
| Curios API | 9.5.1+1.21.1 |
| Player Animator | 2.0.1+1.21.1 |
| Accessories | 1.1.0-beta.53+1.21.1 |
| owo-lib（NeoForge） | 0.12.15.1-beta.6+1.21 |

Aether 自带 Nitrogen 和 Cumulus；需另装表中的 Accessories 新版以替换 Aether 内置的旧版（旧版在开发环境有 Mixin 兼容问题）。玩家安装时需要另外安装上表中的依赖（启动器通常会自动处理依赖）；务必选择 **1.21.1 NeoForge** 文件。

四件饰品同时支持天境饰品栏（Accessories）和对应的通用 Curios 槽：神能法戒支持天境戒指槽／Curios `ring`，紫晶律动项链支持天境吊坠槽／Curios `necklace`，重力晶施法护手支持天境手套槽／Curios `hands`，武神法者披风支持天境披风槽／Curios `back`。两套槽位中的属性、项链施法磨损及披风减伤均生效。天境界面只显示 Accessories 槽位；装备到 Curios 的饰品需通过 Curios 界面查看和取下。四件饰品也支持泛用 Curios `curio` 槽，在其中提供完整属性、项链磨损和披风减伤；不匹配的专用槽位不会触发这些效果。此兼容只声明物品适用的槽位，不额外增加玩家槽位，通用槽位需由其他模组或整合包配置提供。法术书仍使用 Curios 的 `spellbook` 槽。物品标签可由整合包覆盖。

## 构建与运行

在本目录打开终端：

```powershell
.\gradlew.bat build
.\gradlew.bat runGameTestServer
.\gradlew.bat runClient
```

发布文件为 `build/libs/aether_spellbooks-1.21.1-1.2.0-neoforge.jar`。Linux/macOS 使用 `./gradlew`。

客户端截图检查沿用原工程：

```powershell
$env:ASB_RENDER_CHECK = 'armor' # mobs / armor / weapons / items / books / spells / shrines / slider / dungeon / accessories
.\gradlew.bat runClient
Remove-Item Env:ASB_RENDER_CHECK
```

这些命令创建开发测试世界，截图写入 `run-client/screenshots/`。GameTest 类、空测试模板及测试世界数据包均不进入发布 JAR。

## 贴图与模型（法术书之外）

法术书和法术图标之外的全部贴图、模型都在 1.21.1 上重做过一轮，做法与此前的法术书一致：逐像素手工排布，不用噪声、棋盘抖动或缩小模糊的程序化绘画，明暗色阶按材质分档并整体左上方打光，轮廓使用材质自身最深的色调。天境和铁魔法的素材只用于核对构图、比例和画法，像素全部原创。

| 类别 | 内容 | 生成脚本 |
|---|---|---|
| 法剑与锻造 | 4 把法剑、锻造模板、空槽符文 | `tools/item_art.py` |
| 法杖 | 5 把法杖的 3D 造型与 64×64 面图集 | `tools/staff_models.py` |
| 法师甲 | 女武神／凤凰两套 Geo 模型、动画、128×128 图集、披风与 8 个盔甲图标 | `tools/armor_art.py` |
| 施法生物与特效 | 女武神术士、烈阳侍僧皮肤与发光遮罩、羽翼、投射物与光环贴图、4 组粒子 | `tools/entity_art.py` |
| 地牢宝库与召回 | 雕纹／天灵／狱炎宝库的 14 个立体模型、24 张方块贴图、守卫残片与三件圣物图标、三种守卫之魂与仪式光柱 | `tools/dungeon_art.py` |

神能法戒、紫晶律动项链、重力晶施法护手和武神法者披风保留原有的手绘图标，不由脚本生成。

各脚本都可用 `python tools/<脚本>.py` 重建资源，`--check` 只比对资源是否与脚本一致。全工程 25 张带 `.png.mcmeta` 的帧动画贴图（法剑、锻造模板与盔甲共 12 张物品图标，以及法杖图集、法师甲图集、披风和部分实体贴图）平时停在静止帧，每隔几秒出现一次流光、宝石闪烁或符文脉动，图标轮廓在所有帧中保持不变。盔甲图标与穿戴贴图用同一套帧序同步播放。披风的动画由 `MageCapeLayer` 主动推进（GeckoLib 的 `AnimatableTexture`）。

法杖在背包、展示框、手持和地面上都显示 3D 模型，背包与展示框的摆放角度沿用铁魔法自带法杖的参数（`ice_staff.json` 等）。武神权杖的双翼是建模出来的：每侧一块覆羽肩部加四根 3 格宽的实心羽毛，以 0°、22.5°、45°、67.5° 向上、向外展开并互相交叠，羽根金色、羽尖渐白，不画描边，靠方块本身的边和面的明暗表现形状。

盔甲图标沿用原版构图：头盔正面、胸甲与护腿正面、靴子侧面且左右脚尖分别朝外，8 个图标的轮廓都左右对称。武神法者战盔与凤凰法者兜帽都做成开脸样式；凤凰兜帽的模型只保留中间的火冠，面罩开口从眉线一行开始，穿戴时不会遮住眼睛。

`ASB_RENDER_CHECK=weapons|items|armor|mobs|spells` 可生成对应的实机截图（法杖另含每把的第一人称手持图）。法杖墙和盔甲场景在拍摄前会清空上一轮留下的展示框、盔甲架和玩家盔甲，因为测试世界在多次运行之间会复用。

实机对照图见 `docs/screenshots/`：`before_after_summary.png` 为四组同时对照（物品栏、法杖与法剑、法师甲、施法生物），另有各自单独的上下对照图。离线预览（图标逐条对照、动画帧序与 GIF、模型多视角）由各脚本写入 `build/art_preview/`，不进入发布 JAR。

## 法术书模型（1.21.1）

魔石法典、武神圣典和烈阳法典的 3D 模型参考铁魔法的冰霜、金制和烈焰法术书，以每模型单位 1 像素、7×10 像素封面重绘。分别保留灰蓝石面与青色眼纹、蓝色皮面与银白羽翼、暗红皮面与金黄太阳，使用成片的材质明暗和铜／金包角。合书外形为 4×7×10，封皮厚度为 1，书页内收 1，与铁魔法常规书籍的体量一致。32×32 图集为封面、背面、内衬、书脊及书页分配独立 UV；原 16×16 背包图标保持不变。

左右手持显示正面纹饰，第一人称略微缩小、上移，展示框朝向与展开模型同步修正。可重建的图集和模型源脚本为 `tools/build_spellbook_models.py`（需要 Pillow），带 `--check` 参数时只校验导出资源。运行 `ASB_RENDER_CHECK=books` 可生成与铁魔法参考书同尺度、同光照的实机对照、36 帧环绕记录以及左右手和第三人称截图。检查辅助类不进入发布 JAR。

资源与检查记录见 [法术书模型说明](docs/spellbook_models.md)。

## 铁魔法与滑行魔石联动

- **投掷**：扔出的镐子及其他符合天境挖掘工具规则的物品可以唤醒并伤害滑行魔石。投掷工具的伤害为 **法术伤害 + 该工具的攻击伤害**，支持主手／副手、锋利附魔及力量等攻击属性加成；不会借用另一只手中武器的攻击力或重复叠加。物品与伤害在发射时确定，换手或修改原物品不影响飞行中的投射物。普通物品不会因此获得破防能力。
- 无额外加成时，一级投掷的木／石／铁／钻石／下界合金镐面板伤害分别为 **3 / 4 / 5 / 6 / 7**。实际伤害继续经过目标抗性和天境的 `tools_debuff` 规则；默认情况下，天境还会削弱外来投射物，因此实际扣血可能低于面板数值。
- **幽冥锤**：可以直接瞄准 16 格内的滑行魔石施放，复用原有锤子模型、动画和音效，按原动画中锤头下缘的位置对齐滑行魔石顶面，在第 13 tick（约 0.65 秒）落锤时结算一次伤害。生成时锁定挥击方向，尚未消失的锤子特效不阻挡后续施法。目标离开落点、出现墙体遮挡或施法者离开地牢房间时会落空。攻击分支不会挖掉周围方块，普通挖矿用法保持原样。
- 幽冥锤默认基础伤害为 **6 / 8 / 10 / 12 / 14**，受法术强度、唤魔强度、铁魔法的法术倍率配置和目标抗性影响。法术详情新增中英文滑行魔石伤害提示。
- 保留天境的和平难度、地牢房间边界、首次命中唤醒并回满生命、仇恨和受击流程；幽冥锤仍遵守冒险模式限制。碎岩飞刃等既有兼容继续生效。

配置位于 `config/aether_spellbooks-common.toml`；修改后重启游戏／服务器生效：

```toml
[sliderCompatibility]
thrownToolsDamageSlider = true
spectralHammerDamageSlider = true
hammerBaseDamage = 6.0
hammerDamagePerLevel = 2.0
```

联机时以服务端数值为准，客户端使用相同配置可保持法术详情显示一致。兼容通过本附属的四个 Mixin 实现，不需要替换天境或铁魔法的 JAR。

## 地牢宝库与守卫召回（1.2.0）

- **宝库**：地牢 boss 死亡时，其房间中仍上锁、内容尚未生成的藏宝箱转为雕纹／天灵／狱炎立体宝库，沿用原战利品表。每位玩家每轮凭对应钥匙独立开启一次，合并后的全部奖励在开启瞬间一次性弹出。
- **每人一把钥匙**：默认按参战者 UUID 直接发到背包，跨维度照常发放；离线、尚未重生或背包已满时保留待领取钥匙，在线后每秒尝试补发。
- **守卫之魂**：使用岗哨核心、武神誓约或烈阳余烬恢复房间并召回 boss。武神女王恢复整座银牢并直接应战；三种宝库均能抵御滑行魔石撞击。
- **再次挑战**：默认在 boss 复活时重置房间内宝库的领奖记录，下次击杀再次发钥匙。召回的 boss 保留天境原本的击杀掉落，奖励通过宝库领取。
- **铁魔法宝库兼容**：可选开启一次性弹出，并在死者之王使用命匣复活时刷新周围宝库；默认关闭，不影响 Minecraft 原版试炼宝库。
- 只处理属于地牢的 boss；刷怪蛋、指令或其他模组生成的 boss 保持天境原版行为。五个配置项位于 `[dungeons]`，详情见下方文档。

规则、保护措施、物品来源与验证见 [地牢宝库与守卫召回](docs/dungeon_rematch.md)。实机截图：[宝库](docs/screenshots/dungeon_vaults_active.png)、[召回仪式](docs/screenshots/dungeon_ritual.png)、[背包图标](docs/screenshots/dungeon_inventory.png)。

## 验证

本次 `build` 和全部 84 项必要 GameTest 通过（58 项其他测试、6 项饰品测试和 20 项地牢测试）；1.20.1 的构建与 85 项必要测试同样全部通过。地牢测试覆盖钥匙直接入包、跨维度及离线补发、背包已满、独立领奖与复活重置、房间保护、整座银牢恢复、滑行魔石防护和死者之王联动。此前的新增测试覆盖真实投掷施法和换手、各材质镐的投射物伤害与实际扣血、副手锋利附魔及物品快照、力量加成且不重复叠加工具伤害、工具筛选、普通法术仍被拒绝、幽冥锤唤醒与单次扣血、射程／墙体／实体遮挡、冒险与和平模式、地牢边界、移动目标、配置开关、原有挖矿和攻击时不挖方块。

资源侧另有离线校验：`tools/` 下六个生成脚本的 `--check` 全部通过（法术书 3 本 2 模型、法剑与锻造 6 张、法杖 30 个文件、盔甲 27 个文件、生物与特效 31 个文件、地牢 33 张贴图与 14 个宝库模型），25 个 `.png.mcmeta` 的帧数、帧尺寸与帧序号均在图片范围内。

饰品槽位测试确认四件饰品可放进对应的天境和通用 Curios 槽、拒绝不匹配的 Curios 专用槽，且两套 API 提供相同的属性；另有测试验证 Curios 项链施法只磨损一次、磨损后加成增长、耗尽后加成归零，以及 Curios 披风减伤和脱下后恢复正常。Curios 的泛用 `curio` 槽遵循其默认接纳规则，并提供与对应槽位相同的完整效果。饰品效果测试通过正常玩家 tick 读取实际属性，覆盖装备、施法磨损、耗尽、修复和卸下；不匹配的专用槽位不会触发磨损或减伤。测试数据包为玩家提供四种对应槽位及四个泛用槽位，不进入发布 JAR。法术书仍可放进 Curios 法术书槽；`ASB_RENDER_CHECK=accessories` 在真实客户端里模拟右键和天境界面拖放，并截图记录装备结果，随后对比真实客户端与服务端网络同步后的项链耐久和实际法术强度；装备、磨损、耗尽、修复、卸下五个阶段全部一致时输出 `[ASB-ACC-SYNC] all 5 stages passed`。

客户端幽冥锤已从正面和侧面各检查完整的 32 帧序列，包含起手、命中和收招，记录见 [正面动画](docs/screenshots/slider_hammer_front.gif) 与 [侧面动画](docs/screenshots/slider_hammer_side.gif)。运行 `ASB_RENDER_CHECK=slider` 可重新生成连续截图。真实多人联机手感仍需人工体验。

此前已完成客户端盔甲、披风、法术特效和两座神殿在真实天境世界自然生成的截图检查，截图位于 `docs/screenshots/`。

GameTest 神殿测试使用真实天境噪声，在结构注册的放置候选区块生成并验证模板；专用测试服务器关闭自动结构生成，因此此测试直接调用结构生成入口。

## 移植说明

- 改用 NeoForge ModDevGradle、Java 21、DeferredHolder 和新事件接口。
- 装备属性采用 1.21.1 的 Holder、ResourceLocation 属性标识和物品组件；盔甲材质通过注册表注册。
- 迁移 Aether 的附件数据和数据驱动恐鸟类型、Iron's Spells 的投射物与武器接口。
- 更新顶点渲染、客户端皮肤接口以及实体同步数据构建方式。
- 数据包迁移至单数目录、1.21.1 配方输出和附魔战利品格式；内置冰系伤害数据包保持可选。
- NeoForge 的 FakePlayer 禁止骑乘，骑乘测试使用带空连接的 ServerPlayer。专用 GameTest 服务器默认丢弃模组维度，因此测试环境提供独立的平坦主世界与固定天境生物群系预设；只用于测试，随发布 JAR 排除。

饰品泛用槽修复及实际属性、客户端同步检查说明见 [饰品实际属性与同步验证](docs/accessory_effects_fix.md)。
